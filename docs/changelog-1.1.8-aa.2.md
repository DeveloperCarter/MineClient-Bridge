## Resource reload

- New MCP tool `minecraft_client_reload_resources({run_id})`, also sequence step `{kind:"reload_resources"}`. Starts `Minecraft.reloadResourcePacks()` on the render thread, then waits for its future on the HTTP worker so subsequent frames can complete the reload. Returns `duration_ms`; errors retain the reload reason. Authenticated `POST /control/reload-resources`.
- Works with the new mod jar even without the Java agent. Uses the existing identity and isolated-input checks; no desktop input.

## Class hot-swap

- The jar has `Premain-Class: io.github.campione01.mineclientbridge.agent.BridgeAgent` and `Can-Redefine-Classes: true`. No retransformation capability is requested. Launch with `-javaagent:<jar>` as well as loading the jar as an FML mod.
- Set `mineclientBridge.hotswapRoots` to class-output directories separated by the platform path separator (`;` on Windows), and `mineclientBridge.hotswapPackages` to comma-separated package prefixes. Prefix boundaries are enforced; game, NeoForge, JDK, loader, and bridge packages are always excluded. Only files below the configured roots are read. Configure only your own mod's packages/output.
- Premain holds Instrumentation in the **system class loader**. The FML module-layer copy calls the system holder reflectively using only JDK collection/string values; referring directly to the mod copy would read a different, empty static field.
- A no-op transformer hashes initial class-definition bytes after ModLauncher's transformations and compares them with the class file on disk at that definition. Mismatches, missing baselines, and unreadable/ambiguous initial files are treated conservatively as transformed and never redefined. Redefinition does not overwrite those initial observations.
- New MCP tool `minecraft_client_hotswap({run_id})`, also sequence step `{kind:"hotswap"}`. Authenticated `POST /control/hotswap`, dispatched through the Minecraft render executor between frames. Finds changed allowed loaded classes and calls `Instrumentation.redefineClasses` once. If any JVM check fails, the entire batch remains old; hashes advance only on success. No subset retries.
- Report: `swapped[]`, `refused[{class,reason}]`, `transformed[]`, `new_on_disk[]`, `unchanged_count`, `restart_required`, `static_fields_note`, and `skipped_hidden_count`. `new_on_disk` means allowed class files not currently loaded (including pre-existing lazy classes), not a request to eagerly load them. `transformed` lists all observed transformed/unknown file-backed loaded classes, even unchanged ones, so its presence always sets `restart_required`. JVM-generated hidden lambda classes have no disk file or transformer baseline and are unmodifiable; they are excluded and counted separately, rather than falsely labelled as transformed mod classes. A refusal is a successful report with an empty `swapped`, rather than an HTTP failure; inspect the report before continuing.
- No agent: clear `agent not loaded` error. Static fields retain their values and static initializers do not run again. Existing active stack frames finish their old bytecode; a later invocation uses the new body. Registrations and JVM schema changes need a restart.
- Resource reload/hot-swap requests allow up to 120 seconds of client work; MCP HTTP timeout is 125 seconds. A timeout does not claim successful completion. All reports include the static-state caveat; the existing response-size bound still applies.
